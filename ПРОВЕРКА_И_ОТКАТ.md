# Проверка котла Haier и откат обновления

## Что можно проверить сейчас

Установленную пару **0.3.16b0 + 0.3.0** пока можно оставить без изменений. Предварительный выпуск **0.4.0b1** подготовлен отдельно. Перенос в основную ветку `main` и установка в ваш HA — разные действия; эта инструкция сама по себе ничего не устанавливает.

### 1. Посмотреть результаты автоматических тестов

1. Откройте [успешный запуск GitHub Actions](https://github.com/burner98/haier_evo/actions/runs/43481379436).
2. Проверьте зелёные отметки у `test (2026.10.4)`, `test (2026.11.1)` и `lint`.
3. В каждом задании `test` откройте шаг запуска проверок. В конце журнала должно быть **336 passed** — 336 тестов пройдено.
4. Задание `publish` подтверждает публикацию архива. [Предварительный выпуск](https://github.com/burner98/haier_evo/releases/tag/v0.4.0b1) должен иметь отметку **Pre-release**.

Это проверка нового кода без вашего котла и аккаунта EVO. Одна служебная отметка предупреждения тестовой среды HA 2026.11 не означает провал тестов; ориентир — итог задания и число пройденных тестов.

### 2. Посмотреть текущую установленную интеграцию — без изменений

1. В HA откройте **Настройки → Устройства и службы**.
2. Найдите **Haier Evo** и **Haier Evo — котёл TechLine S**.
3. Если запись котла отключена пользователем, оставьте её отключённой. Это ожидаемо для прежнего состояния установки и не доказывает ошибку нового выпуска.
4. В разделе **Сущности** отфильтруйте записи дополнительной интеграции котла. Запишите или сделайте снимок их текущих `entity_id` — полных имён вида `sensor.…`, `switch.…`, `climate.…`. Не меняйте их.
5. Ожидаются следующие **10 сущностей**:

| Платформа | Название | Постоянный ключ |
|---|---|---|
| Климат | Отопление | heating |
| Переключатель | Питание котла | power |
| Переключатель | Eco | eco |
| Датчик | Температура теплоносителя | ch_temperature |
| Датчик | Мощность горелки | burner_power |
| Датчик | Ступень антизамерзания | antifreeze_level |
| Датчик | Текущая авария | current_alarm |
| Двоичный датчик | Пламя | flame |
| Двоичный датчик | Требуется обслуживание | service |
| Двоичный датчик | Авария котла | alarm |

Полные имена могут включать имя устройства; ваши переименования сохраняются. Формат `unique_id` остаётся `haier_evo_boiler_<идентификатор устройства>_<ключ>`. Конкретные `entity_id` зависят от существующего реестра, поэтому сравнивайте со своими сохранёнными значениями, а не с выдуманным примером.

При выключенном из электросети котле или отключённой записи сущности могут быть **недоступны**. Это не подтверждает и не опровергает совместимость нового кода: он пока не установлен. Если сущности не видны, включите отображение отключённых/недоступных записей в фильтрах; не добавляйте интеграцию заново ради проверки.

**На этом проверку текущего HA можно закончить.** Не включайте запись, не нажимайте «Питание котла», не включайте отопление, не меняйте температуру и не запускайте автоматизации для проверки нового выпуска.

## Как повторить тесты самостоятельно

Этот раздел — для отдельного компьютера или тестового сервера с Git, Docker и оболочкой Linux/macOS/WSL. В установленном HA выполнять команды не нужно. Windows PowerShell без Docker и оболочки Linux для этих команд не подходит.

1. Скачайте репозиторий и переключитесь на точный опубликованный выпуск:

```sh
git clone https://github.com/burner98/haier_evo.git
cd haier_evo
git checkout v0.4.0b1
```

2. Выполните полный прогон в двух контейнерах HA:

```sh
sh scripts/run_checks.sh 2026.10.4
sh scripts/run_checks.sh 2026.11.1
sh scripts/run_lint.sh 2026.11.1
```

Первый запуск скачивает образы HA и зависимости, поэтому нужен интернет и свободное место. Исходный код подключается к тестовым контейнерам только для чтения; настройки рабочего HA и настоящие токены в них не передаются.

Ожидаемый результат: **336 passed** на каждой версии HA; проверка кода завершается без новых ошибок. При ошибке сохраните ссылку/журнал, версию HA и название неудачного теста. Пароли, токены и полный файл `.storage` отправлять не нужно.

### Что проверяет имитатор

| Проверка | Ожидаемое поведение |
|---|---|
| Существующий реестр | Все 10 `unique_id` и сохранённых `entity_id` совпадают; дублей нет |
| Асинхронная команда | Отправка ожидается через `await`; ошибка транспорта доходит до вызывающего кода |
| Подтверждение состояния | Температура/переключатели не меняются локально только из-за отправки команды |
| Облако, котёл или кэш недоступны | Управляющая команда отклоняется |
| Переподключение | До свежего REST-состояния управление запрещено |
| Запоздавший REST-ответ | Более новое сообщение устройства не затирается |
| Аварии | Явная авария появляется и очищается; температура 43 не считается кодом аварии |
| Выгрузка | Подписки снимаются, незавершённое чтение отменяется |
| Перезагрузка базовой интеграции | Старый объект становится недоступным, планируется перезагрузка дополнительной интеграции |
| Задание ниже 35 °C | В подставной транспорт уходит 35 °C |
| Выключение отопления | Отключается контур отопления; команда выключения питания котла не отправляется |

Последние две проверки выполняются **только на имитаторе**. Они не являются предложением отправлять такие команды реальному котлу без газа.

## Будущее обновление HA — отдельный этап

Переходить к этому разделу следует только после отдельного решения об установке. В рамках текущей работы установленный HA не менялся.

1. Создайте полную резервную копию HA через **Настройки → Система → Резервные копии**. Скачайте её и сохраните ключ/аварийный набор восстановления при шифровании.
2. Сохраните текущие версии, список 10 `entity_id` и состояние отключения интеграции. Убедитесь, что в копии есть данные HA, обе папки компонентов и старый файл токенов при его наличии.
3. Скачайте именно `haier_evo-boiler-0.4.0b1.zip` из [выпуска](https://github.com/burner98/haier_evo/releases/tag/v0.4.0b1). Общий архив исходников GitHub — другой файл.
4. Установите обе папки из архива вместе в каталог конфигурации HA: `custom_components/haier_evo` и `custom_components/haier_evo_boiler`. Сохраните прежние папки отдельно; не смешивайте файлы разных версий.
5. Перезапустите HA. Не удаляйте записи интеграций и не создавайте их заново.
6. Проверьте версии: базовая интеграция **2.0.0**, дополнительная — **0.4.0b1**.
7. Сравните все 10 `entity_id` со списком до обновления. Не должно появиться дублей или новых имён с суффиксами `_2`.
8. Откройте журнал HA. Не должно быть ошибок загрузки `haier_evo_boiler`, отсутствующих `runtime_data`, старых методов API или сообщений о не дождавшейся выполнения корутине.
9. Если запись котла ранее была отключена, она должна остаться отключённой. При выключенном котле недоступность допустима. Не включайте его и не отправляйте команды только ради проверки установки.

Подтверждение связи с реальным котлом, работа пламени, горелки, реальных аварий и защит — отдельная проверка при штатном вводе котла в эксплуатацию по инструкции производителя с соответствующим специалистом. Автоматические тесты этого не заменяют.

## Когда остановиться и откатиться

Причины для отката: интеграция не загружается; появились дубли; изменились существующие `entity_id`; повторяются ошибки нового API; HA стал нестабилен после обновления.

1. Сохраните журнал ошибки без паролей и токенов.
2. Восстановите **полную резервную копию, сделанную до обновления**, включая данные HA и обе прежние папки компонентов. Полное восстановление вернёт и другие настройки HA на дату копии.
3. Если папки компонентов не входят в выбранный способ резервирования, отдельно восстановите их сохранённые версии **0.3.16b0 + 0.3.0** вместе с данными из той же резервной копии.
4. Перезапустите HA и проверьте прежние версии, 10 идентификаторов и прежнее состояние отключения записи.

Точка исходного кода для отката: `7ff38716f4c96e81ff47a20775990ec4247ff242`.

**Возврата только файлов Python недостаточно для гарантированного отката.** Новая базовая интеграция переносит учётные данные в другое хранилище и может удалить прежний файл токенов/сохранённый пароль. Не редактируйте `.storage` вручную и не публикуйте её содержимое.
